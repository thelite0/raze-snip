# Raze Snip

A resident C++20 / Qt 6 capture overlay for KDE Plasma 6 Wayland. Normal capture has no application window. The toolbar follows a Windows Win+Shift+S capture-overlay reference: top-center dark strip, four modes, purple selected tile, close button. Icons use original vector paths rendered directly by Qt Quick Shapes; no raster icon scaling and no Microsoft asset redistribution.

## Use

- **Meta+Shift+S / Print**: freeze the workspace, drag a rectangle, release to copy, overlay closes.
- Toolbar: rectangular, freeform, window, entire workspace, cancel. In window mode, desktop or panel space selects the monitor beneath the pointer; application content selects the window.
- Escape / right click: cancel.
- Tab / Shift+Tab: toolbar focus; Enter / Space activate a focused mode.
- Arrow keys while selecting: nudge 1 logical pixel; Shift+arrow: 10; Enter accepts an existing selection.
- **Shift-release**: copy and save to `~/Pictures/Screenshots/Screenshot_YYYY-MM-DD_HH-mm-ss.png`.
- **Ctrl-release**: copy, dismiss the capture overlay, explicitly open editing.
- `raze-snip --edit`: edit the last capture retained by the running service.

```
raze-snip                 # area selection
raze-snip --area
raze-snip --screen        # active KWin monitor
raze-snip --workspace     # all monitors, no selection UI
raze-snip --save          # area selection; save and copy
raze-snip --copy          # default clipboard-first behavior
raze-snip --annotate      # area selection; explicitly open editor afterward
raze-snip --workspace --save
raze-snip --daemon        # start ready, no UI
raze-snip --quit          # stop resident process
```

Editing supports arrows, rectangles, freehand pen, text, blur, pixelation, numbered markers, sampled colors, stroke width, undo/redo. Editing is separate from the default overlay flow.

## Build and install (Fedora 44)

```
sudo dnf install gcc-c++ cmake ninja-build qt6-qtbase-devel qt6-qtbase-private-devel qt6-qtdeclarative-devel wayland-devel wayland-protocols-devel \
  layer-shell-qt-devel kf6-kglobalaccel-devel kf6-kguiaddons-devel
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/usr/local
cmake --build build
ctest --test-dir build --output-on-failure
sudo cmake --install build
kbuildsycoca6 --noincremental
mkdir -p ~/.config/autostart
cp build/org.raze.snip.autostart.desktop ~/.config/autostart/org.raze.snip.desktop
raze-snip --install-shortcut --daemon
```

Qt Quick Controls and Shapes, Qt Wayland, and KDE's installed runtime libraries are required. A Fedora KDE installation already supplies these. KGuiAddons >=6.29 handles publishing clipboard content without requiring window focus. LayerShellQt gives each output an anchored overlay surface, including over full-screen applications and panels. KGlobalAccel owns the shortcut. No X11 capture APIs, Electron, screenshot portal, or global permission bypass.

For a system package use `-DCMAKE_INSTALL_PREFIX=/usr -DCMAKE_INSTALL_SYSCONFDIR=/etc -DBUILD_TESTING=OFF`. The RPM spec under `packaging/` installs an XDG autostart entry. Desktop and D-Bus files have install paths generated by CMake. The optional `--install-shortcut` action replaces conflicting Meta+Shift+S and Print bindings. Stop any previous resident instance before using it.

## Authorization and backend

The live interface was inspected **before implementation** on KWin 6.7.5, interface version 5. See `docs/live-interface.txt` and `docs/UX-reference.md`.

The installed desktop file declares:

```
X-KDE-DBUS-Restricted-Interfaces=org.kde.KWin.ScreenShot2
```

Run the installed binary: KWin identifies the executable via the desktop entry's absolute Exec path. An uninstalled build binary is intentionally denied. Do not set `KWIN_SCREENSHOT_NO_PERMISSION_CHECKS`.

`CaptureWorkspace`, `CaptureScreen`, and `CaptureWindow` are called directly with an owned Unix pipe FD. Nonblocking reading runs concurrently with the D-Bus reply; image width, height, format, stride, and scale are validated before constructing the image. CaptureWorkspace freezes at KWin's highest output scale. Negative origins are translated from the union of output geometries, and crops use the returned scale. Mixed-scale regions have one pixel grid at KWin's maximum workspace scale, so lower-density outputs are upsampled by KWin.

Window hit testing uses a transient KWin JavaScript script to read stacking order, desktops, activities, and frame geometries. It is unloaded when the overlay closes. Window pixels are then captured directly with CaptureWindow, including decorations and excluding shadows. Desktop/panel targets select one output and use CaptureScreen at that output’s native resolution. If a window changes after activation, its actual capture reflects its state at release; rectangle/freeform captures always crop the frozen workspace.

KWin's screenshot backend renders its standard 8-bit SDR image. PNG output is tagged sRGB. This works with HDR/WCG enabled but does not export an HDR PNG or preserve HDR luminance in the frozen overlay. Visual parity of HDR desktop brightness requires color-managed HDR Wayland surfaces beyond this initial implementation.

## Verification and limits

`raze-snip --smoke-test /absolute/path` briefly shows and exercises the overlay, reads the workspace, selects a 320×200 logical region, publishes PNG clipboard content, and captures a native window. It writes diagnostic images and JSON. Run with the installed binary and stop the existing service first. These diagnostics contain desktop pixels; they are not included in the source package.

Geometry tests cover reverse dragging, negative origins, fractional scale, monitor-spanning crops, clipping, and freeform transparency. The target machine has two 1× outputs (1920×1080 HDR/WCG, 1440×900 SDR). Mixed scales and negative origins are covered by geometry tests, not a live monitor rearrangement. Warm workspace capture readback measured 43–63 ms in one three-run sample; this is backend readback latency, not a claim about physical keypress-to-display timing. Initial startup and system load vary. Opening and closing are unanimated. Dimming and the toolbar appear together. Capture surfaces use KWin’s utility layer-shell classification, which is excluded from its normal-window scale effect and popup fade effect.

Exact pixel parity across Windows builds cannot be certified from a raster at unknown scale. The supplied toolbar image is the visual authority; source measurements and estimates are documented. The default flow omits dimensions/handles and editor controls as requested in the later Windows-parity instruction. Post-selection resize handles and a dimensions badge are not implemented in this version. Keyboard nudging applies during the live selection.

The process stays resident with no windows after capture, both to keep the shortcut ready and to serve image data to Wayland clipboard consumers. Stop it with `--quit`; session autostart restores it at login. Captures are retained only in RAM unless saving is requested. Undo history is limited to 30 full-image states.

During capture, a temporary Wayland pointer constraint suppresses KWin electric corners only within 24 logical pixels of exposed output corners. It is released on movement away, cancellation or capture completion. Monitor seams remain unconstrained. Desktop hot-corner settings are preserved. The Qt platform-native surface accessor requires Qt GUI private headers at build time.
